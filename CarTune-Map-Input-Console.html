CARTUNE // Map Input Console

Fuel · Speed · Engine Calibration — one input surface, every tool, every field checked against your own files

One input surface for every parameter category the tools in your inventory (LinOLS, RomRaider, TunerPro, HyperTuner, LibreTune, Tune-Editor, PCM Hammer, Universal Patcher) can edit, pre-loaded with the calibration targets from your VE SS build sheet. Pick a profile or hand-edit fields, check what's actually writable by which tool, then export a tune_spec.json to hand to whichever editor covers the segment you're touching. This is a spec, not a flashable file — you still open your real base calibration in the matching tool.

Vehicle Not Recognized?

If Discovery came back with no VIN and no ECUs, don't guess — enter what you know and search for a way in. Tier 1 (GitHub) searches live, right here. Tier 2 opens real search results in a new tab for sites that don't allow this page to fetch them directly.

Upload & Inspect a File

Got a file already — an XDF, DBC, ODX, a calibration .bin, a dyno CSV, a tune_spec.json, anything? Drop it here. This detects the type from its extension and contents and reads it right in the browser: DBC gets parsed into messages/signals, XDF/ODX get their table and diagnostic-service names extracted, CSV gets checked against the dyno-log columns the Validator gate needs, JSON gets identified and pretty-printed, and a raw calibration .bin gets a hex-dump preview. Binary calibration files can't be decoded into named tables without a matching XDF/OS-ID — that part still needs PCM Hammer/TunerPro/RomRaider.

Saved Tunes

Every session auto-saves a baseline the moment it reads the ECU, before anything is touched, and again right before any flash. Connect your tune library folder once (the folder that contains vin_repos/) and this reads every vehicle's saved snapshots directly — no more hunting for manifest.json in the file browser. It remembers the folder for next time; you'll just get a quick permission prompt.
