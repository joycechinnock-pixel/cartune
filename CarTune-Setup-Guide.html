Setup & Field Guide

CarTune OS

An open-source vehicle tuning & diagnostic platform — discover, sniff, diagnose, tune, validate, and flash, all through one guarded pipeline. This guide gets the software installed and explains what it actually does before you plug it into a car.

⚠ Modifies vehicle ECUs — read the safety notes below Target: Ubuntu 24.04 LTS 41 automated tests passing
What this is

One pipeline, guarded at every step

CarTune OS wires together open-source CAN-bus, diagnostic, and ECU-tuning tools into a single guided sequence — plug in, scan, sniff, diagnose, tune, validate, flash, save, unplug. Every stage hands off to the next through a plain file you can open and read yourself.

Discover
Scan the bus, read the VIN & ECU list
Sniff
Capture live traffic against known signal definitions
Diagnose
Pull trouble codes & the current calibration
Tune
Edit the map in a real tuning tool, by hand
Validate
Safety limits, dyno-log gate, human confirm
Flash
Write the new map, verify the checksum
Done
Saved to history, bus torn down safely
The one rule that never bends

Nothing gets written to an ECU without a human confirming it — and anything beyond a "Day Use" power stage is refused outright unless a real dyno pull (knock, AFR, coolant) is attached. This isn't a setting you can turn off; it's built into the Validator stage itself.

Before you start

What you need on hand

A computerAny machine that can boot Ubuntu 24.04 — from a USB stick or as a second OS. 32GB+ free disk space if dual-booting.
A USB drive32GB or larger, USB 3.0, if you're going with Option A below.
A CAN adapterCANable / candleLight, comma.ai panda, or similar SocketCAN-compatible interface. This is what actually plugs into the car's OBD‑II port.
Internet accessNeeded once, to download tools and definitions. Not needed while actually working on the car.
Safety first

This software talks directly to your vehicle's ECUs and can write new calibration data to them. A bad flash can leave a module unresponsive. Use the Live USB path (Option A) until you trust the workflow, keep the auto-saved snapshots this tool makes for you, and never skip the confirmation prompt because you're in a hurry.

Choose your setup

Option A: Live USB, or Option B: Dual-Boot

Both run the exact same software. The difference is where Ubuntu lives — and how much commitment you're making to your machine.

Option A

Live USB

Start hereReversible

Boots entirely from a USB stick. Zero risk to your existing Windows or Mac install — nothing touches your internal drive.

  1. Flash Ubuntu to the USB driveUse Rufus (Windows) or balenaEtcher, with the Ubuntu 24.04 LTS Desktop image.
  2. Turn on persistent storageRufus offers a "persistent partition" option — set it to at least 4–8GB, so installed tools and your tune history survive a reboot.
  3. Boot from the USB stickRestart, tap F2 / F12 / Esc at power-on (varies by machine) to open the boot menu, and choose the USB drive.
  4. Choose "Try Ubuntu"You're now running Ubuntu in RAM plus your persistent partition — nothing on the internal disk was touched.
Option B

Dual-Boot

Once you trust itBetter I/O

Installs Ubuntu alongside your current OS. Faster disk access for long CAN-FD logging sessions, and native storage for a growing tune-history archive.

  1. Back up your data firstPartitioning carries real risk to existing files — a full backup is not optional here.
  2. Shrink your existing partitionWindows: Disk Management → Shrink Volume. Leave the freed space unallocated.
  3. Install Ubuntu into the free spaceBoot the same USB installer from Option A, choose "Install Ubuntu alongside Windows," and let it set up GRUB (the boot menu that lets you pick an OS at startup).
  4. Reboot and pick UbuntuGRUB will offer both operating systems every time you start the machine. Keep Windows around for anything CarTune doesn't cover (TunerPro, some OEM tools).
# Either option, once you're at an Ubuntu desktop — this is the common setup:
$ sudo apt update
$ sudo apt install -y can-utils python3-pip python3-venv git docker.io build-essential
$ sudo modprobe gs_usb        # driver for CANable / candleLight adapters
Installing the tools

One script, everything it can safely install

Everything CarTune OS uses lives in one folder. There's a launcher you can double-click, and a terminal command that always works as a fallback.

Easiest

Double-click CarTune-Install.desktop

Opens a terminal and runs the installer for you. The first time only, Ubuntu needs one extra click to trust it as a program rather than opening it as a text file:

  1. Right-click the file → PropertiesIn the Files app (Nautilus), open the Permissions tab.
  2. Check "Allow executing file as program"This is a one-time, per-file setting Ubuntu requires for anything you double-click and run.
  3. Double-click itA terminal opens and installs everything it can. It stays open at the end so you can read the summary.
Always works

Or just run it from a terminal

If double-clicking doesn't behave the way your particular desktop is configured, this does the identical thing:

$ cd CarTune          # the folder you downloaded
$ chmod +x setup_tools.sh
$ ./setup_tools.sh
Safe to re-run

Run it as many times as you like — already-installed tools are skipped or updated, not reinstalled from scratch, and one tool failing to build doesn't stop the rest.

Using it

The everyday commands

# See what setup_tools.sh actually managed to install here
$ python3 cartune_orchestrator.py --list-tools

# Check every tool for new upstream activity (safe, read-only, no car needed)
$ python3 cartune_orchestrator.py --check-updates

# Plug the CAN adapter into the car, then run the full pipeline
$ python3 cartune_orchestrator.py --vin AUTO

# See every saved tune for a specific vehicle
$ python3 cartune_orchestrator.py --list-history --vin <your-vin>

# Go back to a previous tune — still goes through the same safety gate
$ python3 cartune_orchestrator.py --revert <version-id> --vin <your-vin>

The actual map editing — deciding which cells to change and by how much — happens in CarTune-Map-Input-Console.html, a separate file you can open directly in any browser. It doesn't need the orchestrator running; export a tune_spec.json from it and hand that file to the command above with --tune-spec.

Where this actually stands

Tested, and not yet tested

The build sheet doesn't pretend everything below has been run against a real car. Here's exactly what has and hasn't.

Verified

41 automated tests cover every piece of logic that doesn't need real hardware — the dyno-log safety gate, the tune-history snapshot/revert system, the update checker, and the tool-manifest resolution. All passing, no network required to run them.

Not yet run

Nobody has run setup_tools.sh against a live Ubuntu machine yet, or plugged the pipeline into a real CAN bus. It's been reviewed and syntax-checked, not field-tested.

Still manual

Only LinOLS has a verified real launch command. Every other tuning tool (RomRaider, TunerPro, PCM Hammer…) still needs its actual CLI confirmed against its own docs before CarTune can drive it directly.

Recommended first run

Do the first full pass on a car you're comfortable being without for a bit, with the Live USB option, and watch the terminal output the whole way through — especially the human-confirm prompt before anything gets flashed. Treat the very first snapshot it saves as your safety net, not a formality.
